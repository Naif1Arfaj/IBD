# Free hosted demonstration

This configuration requests only a Render **Free** Python web service. It does
not create a paid database, disk or AI subscription. It preserves the existing
prediction, explanation and evidence-search implementations.

## Publish

1. Sign into Render and connect the GitHub repository
   `Naif1Arfaj/IBD`.
2. Create a **Blueprint** from this repository's `main` branch. Render reads
   `render.yaml`. Confirm the service shows **Free**, with no paid resources.
3. Set `DEMO_NURSE_PASSWORD` to a password of at least 12 characters when asked.
   The username is `nurse`. Keep this password in Render's secret environment
   settings; do not commit it.
4. Deploy. The service is named `ibd-care`, so the site is
   `https://ibd-care.onrender.com`.
   Test login, a patient assessment, evidence retrieval, and report generation.
   Inspect the logs if the process exceeds the free instance's memory limit.

Optional direct Blueprint setup:
https://dashboard.render.com/select-repo?type=blueprint

## What visitors should expect

- The app runs on Render, independently of the developer's computer.
- Free services sleep after idle periods; the next visit has a startup delay.
- The URL can be kept for a month, subject to Render's free usage allowances
  and availability. There is no promise of uninterrupted uptime.
- SQLite is ephemeral: new patients, assessments, reports and sessions can be
  lost whenever the server restarts, sleeps or redeploys. Startup restores
  synthetic patients, the three demo scenarios and the nurse login, not
  assessments or alerts added by visitors.
- No persistent disk or paid database is provisioned.
- Optional paid AI summaries are disabled. Existing passage retrieval and
  citations still work without an API key.
- Use synthetic demonstration data only. This is not a production clinical
  deployment. Download reports before closing a demonstration if needed.
- The free service's memory budget must be checked with a full assessment and
  evidence search after deployment; local checks cannot prove cloud capacity.

## Security and operations

Debug mode is off, the secret key is generated by Render, and the exact Render
hostname is allowed automatically. HTTPS redirect, secure cookies, static asset
serving and a trusted Render TLS proxy are configured. Migrations run before
the server starts, with a single application worker to limit memory use.

Do not enable paid upgrades without the owner's approval. Delete the service
in Render after the demonstration period if it is no longer needed.
